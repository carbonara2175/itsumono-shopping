# いつもの買い物 v1.2

毎日の買い忘れを防ぐための、シンプルな買い物リストアプリです。
商品を追加して、購入できたものにチェックを付けられます。追加回数の多い商品は「いつもの商品」として自動的に並ぶため、次回からすばやくリストへ戻せます。

HTML・CSS・JavaScriptだけで作られており、ビルドやパッケージのインストールは不要です。入力した内容はブラウザの`localStorage`へ保存され、ページを閉じたり再読み込みしたりしても同じブラウザで引き続き利用できます。

## 主な機能

- **商品の追加**：商品名を入力し、「追加」ボタンまたはEnterキーでリストへ追加できます。
- **数量と単位の追加**：任意の数量（小数にも対応）と、「個」「本」「袋」「パック」「箱」「切」「g」「kg」「mL」「L」から選んだ単位を商品と一緒に登録できます。
- **カテゴリ別の整理**：10種類からカテゴリを選んで追加すると、買い物リストがカテゴリごとに売り場を回りやすい固定順で整理されます。商品がないカテゴリは表示されません。
- **購入済みの管理**：商品のチェックボックスを選ぶと購入済みになり、商品名に取り消し線が付きます。もう一度選ぶと未購入へ戻せます。
- **購入済み商品の一括削除**：「購入済みを削除」から、チェック済みの商品だけをまとめて削除できます。
- **件数の表示**：買い物リストに入っている商品の総数を表示します。購入済みの商品も件数に含まれます。
- **重複の防止**：同じ商品がすでにリストにある場合は追加せず、メッセージを表示します。英字の大文字・小文字も同じものとして扱います。
- **「いつもの商品」の表示**：商品名ごとの追加回数が多い順に最大5件を表示します。「+」ボタンで前回の数量・単位・カテゴリを追加フォームに呼び出し、内容を確認・変更してから追加できます。
- **ブラウザへの自動保存**：買い物リストと商品の追加履歴を、操作のたびに`localStorage`へ保存します。
- **スマートフォン対応**：画面幅に合わせてレイアウトが調整されます。

## 起動方法

### 必要なもの

- Chrome、Edge、Firefox、Safariなどのモダンブラウザ
- ローカルサーバーを使う場合はPython 3など（任意）

外部ライブラリやNode.jsのパッケージは使用していないため、依存関係のインストールやビルドは必要ありません。

### 方法1：ファイルを直接開く

1. このリポジトリをダウンロード、またはクローンします。

   ```bash
   git clone <このリポジトリのURL>
   cd itsumono-shopping
   ```

2. `index.html`をダブルクリックしてブラウザで開きます。

手軽に試すだけなら、この方法で利用できます。

### 方法2：ローカルサーバーで開く（おすすめ）

プロジェクトのディレクトリで次のコマンドを実行します。

```bash
python3 -m http.server 8000
```

その後、ブラウザで[http://localhost:8000](http://localhost:8000)を開いてください。終了するときは、コマンドを実行したターミナルで`Ctrl + C`を押します。

> `localStorage`はページのオリジン（URLの組み合わせ）ごとに分かれます。直接開いた場合と`http://localhost:8000`で開いた場合、または異なるポートで開いた場合は、それぞれ別の保存領域になることがあります。同じデータを使い続けるには、毎回同じURLで開いてください。

## 使い方

1. **商品を追加する**
   「買うものを追加」で商品名を入力し、必要なら数量と単位、カテゴリを指定して「追加」を押します。カテゴリを選ばなかった場合は「その他」になります。数量は空欄でも、小数でも登録できます。商品名は50文字までです。前後の空白は取り除かれ、途中に連続する空白は1つに整えられます。空欄や、数量・単位・カテゴリにかかわらずすでにリストにある商品は追加されません。

2. **購入済みにする**
   買い終えた商品の左にあるチェックボックスを選びます。チェックを外せば未購入の状態に戻ります。

3. **購入済みの商品を整理する**
   1件以上にチェックを付けると「購入済みを削除」を押せるようになります。押すと購入済みの商品だけがリストから削除され、未購入の商品は残ります。

4. **よく買う商品をもう一度追加する**
   商品を追加していくと、画面下部の「いつもの商品」に商品名単位で追加回数の多いものが最大5件表示されます。数量を付けて最後に追加した商品には「前回 300g」のように表示されます。右側の「+」を押すと商品名と前回の数量・単位・カテゴリが上の追加フォームに入り、数量欄へ移動します。今回の数量やカテゴリを確認・変更して「追加」を押してください。変更したカテゴリは新しい前回カテゴリとして記憶されます。前回数量がない場合、数量と単位は空欄になります。すでにリストにある商品の「+」は押せません。

5. **カテゴリ別のリストを確認する**
   商品は「野菜・果物」「肉類」「魚介類」「卵・乳製品」「パン・麺・穀類」「調味料・乾物」「冷凍・加工食品」「飲料・嗜好品」「日用品」「その他」の順にまとまります。同じカテゴリ内では追加した順を維持します。

## `localStorage`の仕組み

`localStorage`は、ブラウザがWebサイトごとに文字列データを保存する仕組みです。このアプリにはサーバーやユーザー登録がなく、データが外部へ同期されることもありません。商品を追加・チェック・削除するたびに、現在の状態をJSON形式の文字列へ変換して保存します。ページを開いたときは保存済みのJSONを読み込み、画面を復元します。

### 使用するキーとデータ形式

| キー | 内容 | データ例 |
| --- | --- | --- |
| `itsumono-shopping-list-v1` | 現在の買い物リスト。各商品はID、名前、数量、単位、カテゴリ、購入済みかどうかを持ちます。 | `[{"id":"...","name":"牛乳","quantity":"2","unit":"本","category":"卵・乳製品","completed":false}]` |
| `itsumono-item-history-v1` | 商品名ごとの累計追加回数と、最後に登録した数量・単位・カテゴリを持ちます。 | `{"牛乳":{"count":3,"lastQuantity":"2","lastUnit":"本","lastCategory":"卵・乳製品"}}` |

キー末尾の`v1`は保存形式のバージョンを表します。将来データ形式を変更するときに、旧形式と区別しやすくするための名前です。

v1.2でも以前と同じキーを使用します。起動時に、カテゴリがない既存の商品と履歴には「その他」を補います。商品、数量、単位、購入済み状態、追加回数などはそのまま引き継がれます。

### 保存について知っておきたいこと

- 「購入済みを削除」で消えるのは現在の買い物リストだけです。追加回数の履歴は残るため、その商品は引き続き「いつもの商品」の候補になります。
- ブラウザの履歴・サイトデータから当該サイトのデータを削除すると、保存内容も消えます。
- シークレット／プライベートブラウジングでは、ウィンドウを閉じたときに消える場合があります。
- 別のブラウザ、端末、ユーザー、URLには自動で共有されません。
- 保存データがJSONとして読み込めない場合や想定外の形式の場合は、アプリが停止しないよう空の初期状態を使用します。
- データを初期化したい場合は、ブラウザの開発者ツールの「Application」または「Storage」から、上記2つのキーを削除してページを再読み込みします。

## v2.0共有機能の準備：家族グループ

v2.0共有機能開発の準備として、Supabaseに`households`テーブルを追加するSQLを用意しました。`households`は、夫婦が買い物リストを共有するときの「家族グループ」を表すテーブルです。

- `id`：家族グループを識別する番号です。登録時にUUIDが自動で作られます。
- `name`：「わが家」など、家族グループの表示名です。
- `created_at`：家族グループを作成した日時です。登録時に自動で記録されます。

RLS（行単位でデータへのアクセスを制限する仕組み）は有効ですが、アクセス許可ルール（RLSポリシー）はまだ設定していません。そのため、ブラウザからこのテーブルを利用する段階ではありません。今後、`household_members`とSupabase Authを用意してから、所属する家族だけがアクセスできるルールを追加します。

### SQLの実行方法

1. Supabaseのダッシュボードで対象プロジェクトを開きます。
2. 左側のメニューから「SQL Editor」を開き、「New query」を選びます。
3. `supabase/001_create_households.sql`の内容をすべてコピーし、SQL Editorへ貼り付けます。
4. 「Run」を押して実行します。
5. 「Table Editor」で`households`テーブルを開き、必要に応じて`name`へ「わが家」と入力して1件を手動登録します。`id`と`created_at`は自動で入るため、入力は不要です。

SQLはテーブル作成とRLSの有効化だけを行い、テストデータは自動登録しません。また、Secret key、service_role key、パスワードなどの秘密情報も含みません。

## v2.0共有機能の準備：家族メンバー

共有機能の第2段階として、`household_members`テーブルを追加するSQLを用意しました。`households`が「家族そのもの」を表すのに対し、`household_members`は「その家族に誰が所属しているか」を表します。

- `household_id`：家族を識別するIDです。`households`テーブルの`id`を参照します。
- `user_id`：Supabase Authで作られるユーザーIDです。Authの`users`に登録されたユーザーを参照します。
- `created_at`：ユーザーが家族へ登録された日時です。登録時に自動で記録されます。

`household_id`と`user_id`の組み合わせが主キーなので、同じユーザーを同じ家族へ重複して登録することはできません。また、`user_id`には検索用のindexがあり、ユーザーが所属する家族を探しやすくしています。将来、夫婦2人を同じhouseholdへ登録することで、2人が同じ買い物リストを共有できるようになる予定です。

このテーブルでもRLSは有効ですが、RLSポリシーはまだ作成していません。Supabase Authでユーザーを作成した後のステップで、自分が所属しているhouseholdを確認し、そのhouseholdの買い物データだけを操作できるポリシーを設定します。今回はユーザーがまだ存在しないため、INSERT文やテストデータも含めていません。

### 家族メンバー用SQLの実行方法

先に`supabase/001_create_households.sql`を実行して`households`テーブルを作成してから、SupabaseのSQL Editorへ`supabase/002_create_household_members.sql`の内容を貼り付けて実行します。この段階ではメンバーを手動登録する必要はありません。

## v2.0開発 Phase 1：Supabase接続テスト

### Phase 1の目的

Phase 1は、GitHub Pages上の静的なWebページからSupabaseへ接続し、学習用の商品を保存・取得・削除できることを確かめるための実験です。認証、ログイン、家族共有、Realtime同期はまだ扱いません。

Supabaseは、クラウド上でデータベースなどを利用できるサービスです。このPhaseでは、専用テーブル`phase1_test_items`だけを使用します。**現在の本番アプリは引き続き`localStorage`を使用しており、本物の買い物データはSupabaseへ移していません。** `index.html`の動作や既存データには影響しません。

### テスト用ファイルの役割

- `supabase-test.html`：本番の`index.html`とは独立した接続テスト画面です。商品名を1件ずつ保存し、Supabaseから取得した一覧の表示と削除ができます。ページを開くたびに一覧を取得し直します。
- `supabase-config.js`：接続先のProject URLとPublishable keyを設定するファイルです。ファイル内の2つのプレースホルダーをSupabaseダッシュボードに表示される値へ置き換えます。
- `supabase-test.js`：`@supabase/supabase-js` v2を使い、`phase1_test_items`への保存・取得・削除を行います。
- `supabase-test.css`：スマートフォンでもテスト操作をしやすくする、このページ専用の見た目です。

### 接続設定と安全上の注意

1. Supabaseで`phase1_test_items`テーブル（`id`、`name`、`created_at`列）を用意します。
2. テストに必要な`SELECT`、`INSERT`、`DELETE`だけを許可するRLSポリシーを設定します。Publishable keyだけではRLSを回避できないため、ポリシーがない場合は画面にエラーが表示されます。
3. `supabase-config.js`の`YOUR_SUPABASE_URL`をProject URLへ、`YOUR_SUPABASE_PUBLISHABLE_KEY`をPublishable keyへ置き換えます。
4. GitHub Pagesの`supabase-test.html`を開き、保存、再読み込み、削除を試します。

Publishable keyはブラウザ側で使うための公開可能なキーです。ただし、データへのアクセス範囲は必ずSupabaseのRLSポリシーで制限してください。**管理者権限を持つSecret keyは、PublicなGitHubリポジトリへ絶対に書いてはいけません。** このテストにもSecret keyは不要です。

## 開発時のポイント

フレームワークを使わない小さな構成なので、変更後はブラウザを再読み込みすれば確認できます。JavaScriptを変更したときは、少なくとも次の流れを確認すると安心です。

1. 商品を追加できること
2. 空欄と重複入力でメッセージが出ること
3. チェック状態が再読み込み後も残ること
4. 購入済みだけを削除できること
5. 「いつもの商品」の順番と「+」ボタンが正しく動くこと
6. ブラウザの開発者ツールでエラーが出ていないこと
